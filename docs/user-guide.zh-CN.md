# Gearhouse 使用说明

## 装备与活动

- 装备树支持任意层级、展开收起、多选和拖放。拖动装备行右侧的手柄，目标行高亮时松开；多选后可整批拖动。先连续调整，最后统一保存；拖到“顶层装备”可解除所属关系，拆下备用请用“拆下”放入库存。
- 保存树修改时可选择“变更装配”并指定生效日期，或“整理层级”修正同一根装备内的共同历史时段。
- 装备支持新增、编辑、复制、购买日期、退役、隐藏、添加新组件或已有装备。复制出的装备保留原名称并放入库存，同类别同名的库存装备合并显示数量；可带上提醒规则，新装备从零累计，单独设置购买日期和装配。
- 装备页可切换“使用中／库存”。库存按类别保留组件树，支持查找、类别筛选、新增待装装备，以及多选后放入库存；没有上级的自行车、鞋和骑行台不会自动归入库存。
- 同类别、同名称的独立库存装备合并显示为“名称 ×数量”，展开后逐件查看和操作。同名装备以数字区分，里程、历史和附件仍各自保留；装上一件后，其他件继续留在库存。整套装备及其子组件保持树形展示。
- “添加组件 → 已有装备”支持类别筛选，并显示库存／使用中状态及累计距离。切换类别保留已选装备，可跨类别多选。
- 组件详情或长按菜单中的“更换”只允许同一类别的装备。可从库存选择，也可直接新建；新建类别固定为旧件类别。旧件默认放入库存，也可退役。整套组件可随旧件保留，或选择转装到新件。
- “拆下”将组件放入库存；库存组件可“装到装备”，独立使用的装备可“取出使用”。装配目标已有同类别组件时，需明确选择替换哪一件或作为新增组件。每件实物保留自己的累计值、保养记录、提醒、图片和附件，装回后继续累计。
- 更换、入库和取出按日期记录。更换历史可整体编辑或删除，相关装上、拆下和库存状态一起修改；同日冲突或已有后续装配时需先处理原记录。已有活动快照保持原样，涉及过去活动时可预览重算。远端活动明确使用了当时在库存的主装备时，保留活动事实并提示核对使用日期。
- 装备页菜单中的“装备类别”支持新增和编辑类别；每个类别可设置名称、基础类型和“计入室内骑行距离”。新增／编辑装备时也能直接创建类别。自定义类别保留基础类型的活动选择和 Intervals.icu 同步能力。
- 内置 23 类：自行车、跑鞋、锁鞋、锁片、锁踏、功率计、车把、坐垫、坐杆、牙盘、曲柄、盘爪、轮组、轮胎、内胎、来令片、碟片、飞轮、链条、前变速器、后变速器、骑行台、其他装备。“车轮”统一归入“轮组”，前后轮可用名称区分；“传动系统”不再是默认类别。
- 骑行台、链条、飞轮、牙盘、曲柄、盘爪和前后变速器默认计入室内骑行距离，其他类别默认关闭。规则只用于新活动和主动重算；修改类别不会重写已有活动。类别随完整备份保存。
- 装备详情按“历史／活动”切换，支持装配记录增删改、保养／摔车／滴蜡／煮蜡等事件，以及活动日期范围统计。历史仅显示本装备的记录；点击“时间线”可在独立页面查看本装备及当时所属组件的装配与维护记录，点按一条记录可打开对应装备并定位到该记录。组件换车后，原车的时间线仍能查到此前的记录。
- 装配按日期记录，从当天开始生效。同一件装备同一天以最后一次归属为准。已有带时刻的装配历史会自动转为整天；转换前保留一份本机恢复版本，已有活动的装备归属和累计值保持原样，需要时可主动重算。
- 历史快照按所选日期重建装备树和累计值，只读查看。
- 活动支持主装备、锁鞋、骑行台选择；组件来自活动发生时的装配。保存主 Gear 变更时立即回写 ICU，并回读确认。
- 重算支持单件装备、装备与组件或整个类别，可选择日期范围、保留手动修改，并在应用前预览差异。涉及导入的历史累计值时需明确确认。
- 删除装备先进入回收站，可恢复；永久删除只需确认，不需要输入名称。
- 装备、事件和活动均可添加图片。支持装备封面、图片排序、浏览和删除。
- 装备详情的“附件”可保存发票、保修凭证和说明书，支持 PDF 与图片，每个文件不超过 20 MB。附件可直接预览、分享或删除，随完整备份保存。

## 装备提醒

在装备详情右上角菜单选择“添加提醒”，填写事项，再选择“累计里程达到”“再使用”或“到指定日期”。默认一次性提醒；“更多选项”可设置天数、保养／装配起点及重复。也可以从一条保养记录的菜单直接添加，自动选中该记录。

提醒显示在装备详情，支持编辑、暂停、完成、明天提醒和删除。基于保养记录的重复提醒会随同类记录开始新周期；固定日期按原日程重复。组件换车不会丢失使用量。距离统计沿用已保存的活动快照和距离计入规则；隐藏装备继续提醒，退役和移入回收站暂停，永久删除时移除提醒。提醒随原生备份保存，通知授权需在新设备单独开启。

首次创建提醒时请求系统通知权限。日期提醒由系统本地投递，距离提醒在活动同步或相关数据变化后检查；iOS 后台调度不能保证骑行结束立即通知。固定日期重复会提前安排后续 12 轮，并在应用运行时补充；系统待发请求总数控制在 60 条以内，长期不打开应用时不能无限补排。

## 同步与数据

首次读取装备时包含 ICU components、装配关系和可用历史基数。以后以本地装配为准，不回写装备树。

自动同步只提供一个开关。前台定期检查，后台通过 iOS App Refresh 请求机会；后台执行时间由系统决定，不能保证固定五分钟。打开应用后会补齐离线期间的数据，历史补录可选任意日期范围。

同步会更新活动数据及非手动覆盖的远端 Gear 归属。列表中缺失的活动会逐条查询，只有确认 HTTP 404 才标记删除并移除对应使用量。主 Gear 写入失败会保留本地选择，并在活动详情提供重试。

新导入及重算的 Virtual Ride／骑行台活动按每件装备所属类别决定是否累计距离；室外活动正常累计。活动次数和时长继续保留。旧活动继续采用已保存的距离计入结果；在类别编辑页可对该类别的装备统一预览重算。

API Key 存入本机 Keychain，不包含在备份里。图片重新编码为有尺寸限制的 JPEG，去掉原始附带元数据。

## 备份与恢复

在“同步 → 备份与恢复”开启“iCloud Drive 自动备份”，首次选择 iCloud Drive 中的文件夹。装备、库存状态、更换记录、装配历史、活动归属、保养记录、类别、提醒、图片和附件一起保存；连接密钥和通知权限不随备份恢复。

数据修改后自动生成版本，无变化时不重复备份。应用在前台时检查备份，后台执行机会由 iOS 决定；关闭应用后不保证立即产生新版本。只有 iCloud 确认文件上传后才显示为最近备份；上传失败会保留已有版本。

“恢复备份”可按时间选择版本并查看内容数量。恢复会替换本机数据，先检查文件和附件完整性，再保留恢复前的本机版本。恢复前版本也能从列表中选择。不同 Intervals.icu 账户的备份不能覆盖当前账户。

自动清理只在新版本上传并通过完整性检查后执行，保留最近 3 份，以及最近 7 天的每日版本和最近 4 周的每周版本。恢复前的本机版本独立保留。

“更多备份操作”提供立即备份、重新选择文件夹和 JSON 导入／导出。更换手机后，选择原 iCloud Drive 文件夹即可读取其中的版本；恢复数据后重新连接同一 Intervals.icu 账户。备份保存到所选文件夹里的 `Gearhouse Backups`，不需要自建服务器。

## 从网页版迁移

在 Mac 上导出完整备份（只读访问 Gearhouse 数据库和图片，不读取连接凭据）：

```sh
python3 scripts/export-web-backup.py \
  --data-dir "$HOME/Library/Application Support/Gearhouse/data" \
  --output "$HOME/Desktop/Gearhouse-backup.json"
```

把文件发送到自己的 iPhone，在 Gearhouse“同步 → 备份与恢复 → 更多备份操作 → 导入备份”中选择并确认。完整备份包含图片；网页版仅导出的图片索引 JSON 无法恢复缺少的图片文件。导入前的本机版本可从“恢复备份”列表找回。导入后在手机重新输入同一 ICU 账户的 API Key。

已有原生原型数据自动迁移到 `state-v2.json`；旧 `state.json` 保留。

## App 图标

图标源文件为 `GearhouseApp/GearhouseIcon.icon`，可用 Xcode 附带的 Icon Composer 打开。1024 × 1024 的链节 G 主体与链轴细节使用独立 SVG 图层；默认外观为暖白底、蓝色 G，深色外观为深蓝底、银白 G。Mono 使用白色主体与灰色链轴，由系统应用透明和着色外观。玻璃效果保留轮廓高光，关闭额外投影。

项目资源阶段编译 `.icon` 文件，主图标名设为 `GearhouseIcon`。系统负责圆角遮罩和各场景尺寸，修改图层后直接重新构建。个人开发团队和 Bundle ID 可在 `Config/Local.xcconfig` 中设置。
